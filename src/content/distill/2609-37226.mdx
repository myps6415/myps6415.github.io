LLM 在文件叢林裡常常迷失，找到的資料總是片段。過去 agent 用迭代搜彚補足，卻不斷重複造輪子，成本飆升卻收效有限。CorpusMap 讓文件自己開口說話——以實體為針，每個文件都是線的終點。

用 7 個模型、3 個資料集測試，CorpusMap 在答案品質和找到的證據數量都勝過直接搜彚，消耗也更少。它把「文件之間的關係」預先算好存在那裡，查詢抵達時直接取用，不需要每次重新推斷。

讓我最有感的是這個前提：當文件之間的關係是客觀存在的事實，每次查詢都重新發現，代價最高——不只浪費 tokens，更容易漏掉關鍵輔助證據。CorpusMap 把這筆代價預支在建構階段，之後每筆查詢都因此變輕。

我有點好奇這在大型文件庫上的表現——Entity Page 的品質會不會稀釋？但它既然是離線建構的，原則上可以做更深的分析，不需要被推斷時間壓著走。

如果你也在處理由文件構成的專案系統，這篇值得讀。它回答的不是「怎麼讓 LLM 搜得更勤」，而是「怎麼讓文件自己說清楚它屬於哪個脈絡」。
